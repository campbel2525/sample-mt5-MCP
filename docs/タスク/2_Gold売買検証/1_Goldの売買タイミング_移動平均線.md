# 目的

GOLDのM30でSMA5がSMA60をゴールデンクロスした後、どの売却条件が過去データ上で良好だったかを比較する。

デッドクロスの時間足と比較対象を変え、どの移動平均線のデッドクロスで売却するのが良いかを同一データ・同一ルールで検証する。

本検証は過去データを使ったシミュレーションであり、MT5への注文、ポジション変更、決済は行わない。

# ゴール

- 移動平均線による売却条件6通りを機械的に比較できるようにする。
- 各売却条件について、全期間、期間前半70%、期間後半30%の成績を確認できるようにする。
- スプレッドを考慮しない共通条件で比較できるようにする。
- 各取引の買いシグナル、買値、売りシグナル、売値、損益、保有時間を追跡できるようにする。
- 入力データ、クロス一覧、取引明細、集計結果を実行フォルダへ保存し、同じ入力を使った検証であることをSHA-256で確認できるようにする。

# 検証対象

## 銘柄

- GOLD
- 買い取引だけを検証する。
- 売りから入る取引は検証しない。

## 使用する時間足

- M5
- M15
- M30

M30は買いシグナルの判定に使用する。

M5、M15、M30は売りシグナルの比較に使用する。

## 指定した検証期間

- 開始日時: `2024.08.26 00:00:00`を含む。
- 終了日時: `2026.08.26 00:00:00`を含まない。
- 時刻はMT5取引サーバー時刻として扱う。
- UTCオフセットは確認できていないため、UTCやJSTへの変換は行わない。

検証時は、M5、M15、M30のすべてでSMA60のクロス判定と売買が可能な共通期間だけを使用する。

実際に使用した開始日時と終了日時は、バックテスト実行後に`backtest_summary.json`の`effective_from`と`effective_to`で確認する。

準備済みのM5はMT5 MCPから99,999本返却され、先頭が`2025.03.27 03:40:00`であるため、指定した2年間より検証期間が短くなる。

# 検証条件

## 使用する指標

### 移動平均

- 短期: SMA5
- 中期: SMA20
- 長期: SMA60
- 計算対象価格: 終値`CLOSE`
- 移動平均方式: 単純移動平均`SMA`

今回の売買条件には移動平均線だけを使用する。

固定利確率、RSI、波動、ローソク足パターン、その他のテクニカル指標は売買条件に使用しない。

時刻`t`のSMAは、時刻`t`を含む直近N本の終値の算術平均として計算する。

```text
SMA_N(t) = (Close(t-N+1) + ... + Close(t)) / N
```

計算はMQL5ではなく、Pythonの次の実装で行う。

- `project/services/chart_service.py`: SMAを計算する。
- `project/services/cross_scan_service.py`: 履歴全体からクロスを抽出する。
- `project/services/backtest_service.py`: 買いと売りを組み合わせて検証する。
- `project/scripts/find_ma_crosses.py`: 入力、クロス抽出、バックテスト、ファイル出力をまとめて実行する。

シェルとDocker ComposeはPythonプログラムを起動するために使用するだけで、SMAやクロスの計算は行わない。

## クロスの判定方法

ローソク足を目視したり、波動を裁量で判断したりせず、各時間足の全バーを時刻順に一括計算して判定する。

### ゴールデンクロス

現在のバーを`t`、1本前のバーを`t-1`とする。

次の両方を満たした現在バーをゴールデンクロスとして記録する。

```text
SMA5(t-1) <= 比較対象SMA(t-1)
SMA5(t)   >  比較対象SMA(t)
```

買い判定で使用する比較対象はSMA60だけとする。

### デッドクロス

次の両方を満たした現在バーをデッドクロスとして記録する。

```text
SMA5(t-1) >= 比較対象SMA(t-1)
SMA5(t)   <  比較対象SMA(t)
```

売り判定では、SMA20とSMA60をそれぞれ比較対象とする。

### 確定足

- 入力履歴の末尾1本は未確定足として除外する。設定値は`end_bar_shift=1`とする。
- SMAとクロスは除外後の確定足だけで判定する。
- SMA60そのものには60本必要であり、クロス判定には現在バーと1本前のバーの両方でSMA60が必要となる。
- クロスが成立したバーの途中では売買せず、クロス確定後に存在する次の同時間足で売買する。

## 買い条件

M30でSMA5がSMA60をゴールデンクロスした場合だけ、買い候補とする。

買いシグナルが成立したM30バーの次に存在するM30バーの始値で買ったものとして扱う。

```text
買いシグナル: M30 SMA5 / SMA60 ゴールデンクロス
買い時刻: 次に存在するM30バーの開始時刻
基本買値: 次に存在するM30バーの始値
```

次のM30バーが検証可能範囲に存在しない場合、その買いシグナルは使用しない。

## 売却条件

### デッドクロスだけで売却する条件

次の6通りを検証する。

| No. | 時間足 | 条件                      |
| --: | ------ | ------------------------- |
|   1 | M5     | SMA5がSMA20をデッドクロス |
|   2 | M5     | SMA5がSMA60をデッドクロス |
|   3 | M15    | SMA5がSMA20をデッドクロス |
|   4 | M15    | SMA5がSMA60をデッドクロス |
|   5 | M30    | SMA5がSMA20をデッドクロス |
|   6 | M30    | SMA5がSMA60をデッドクロス |

デッドクロスが成立したバーの次に存在する同時間足の始値で売却したものとして扱う。

### 条件数

```text
移動平均線のデッドクロス: 6通り
合計: 6通り
```

## 売却条件が成立しなかった場合

- どの売却条件も検証期間内に成立しなかった場合は、共通検証期間内の最後の確定M5終値で強制決済する。

## ポジションの決まり

- 各売却戦略を独立して検証する。
- 1戦略につき同時に保有できるポジションは1つだけとする。
- ポジション保有中に新しい買いシグナルが出ても追加購入しない。
- 既存ポジションの売却時刻と同じ時刻に実行される買いシグナルも使用しない。
- ナンピン、ピラミッディング、部分決済、損切り、トレーリングストップは行わない。
- ロット数、証拠金、レバレッジ、口座通貨換算は計算しない。

## スプレッドとコスト

今回の検証ではスプレッドを考慮しない。

```text
買値 = M30の基本買値
売値 = 売却条件で決まった価格
損益 = 売値 - 買値
```

入力データに`spread`が含まれていても、損益とリターンには使用しない。

次のコストは今回の検証に含めない。

- スプレッド
- 手数料
- スリッページ
- スワップ

## 集計

各戦略について、次の3期間を集計する。

- `overall`: 共通検証期間の全体
- `first`: 共通検証期間を時間の長さで分割した前半70%
- `second`: 共通検証期間を時間の長さで分割した後半30%

分割日時は、検証時に確定した共通検証期間から計算する。

取引の買い時刻が分割日時より前なら`first`、分割日時以降なら`second`へ分類する。

各期間で次を集計する。

- 取引数
- 強制決済数
- 平均保有時間
- 最大保有時間
- 平均MFE
- 平均MAE
- 勝ち数
- 負け数
- 損益なしの数
- 勝率
- 合計価格差
- 単純リターン合計
- 平均リターン
- 中央値リターン
- 最大リターン
- 最小リターン
- プロフィットファクター

MFEとMAEは基本買値を基準に計算する。

```text
MFE = (保有中の最高価格 - 基本買値) / 基本買値 × 100
MAE = (保有中の最安価格 - 基本買値) / 基本買値 × 100
```

保有中の最高価格と最安価格は、買い時刻から売り時刻直前までのM5と、買値、売値から計算する。

売却条件の順位は付けない。

## 入力データの検証

バックテスト開始前に次を確認する。

- GOLDのM5、M15、M30が各1件ずつ存在する。
- 各時間足の履歴が1本以上存在する。
- 日時が`YYYY.MM.DD HH:MM:SS`形式である。
- 日時が重複していない。
- 日時が昇順である。
- 前後バーの時刻差が時間足の分数で割り切れる。
- OHLC、tick volume、spreadが`TechnicalChart`の入力条件を満たす。
- 末尾バー除外後も履歴が残る。
- SMA60クロスを判定できる本数がある。
- 指定された開始日時が終了日時より前である。

バー間隔が通常の時間足より長い箇所は、`interval_gap_count`と`maximum_interval_gap_minutes`として集計結果へ記録する。

週末や市場休場による間隔も含まれるため、間隔が長い箇所の存在だけではデータ欠損とは確定しない。

## 検証方法

MCPから取得したM5、M15、M30を1つの入力JSONへまとめ、Pythonプログラムへ一括入力する。

Pythonプログラムは次の順番で処理する。

1. 入力JSONと各時間足の履歴を検証する。
2. 各時間足の全バーについてSMA5、SMA20、SMA60を一括計算する。
3. SMA5対SMA20、SMA5対SMA60のゴールデンクロスとデッドクロスを抽出する。
4. M30のSMA5対SMA60ゴールデンクロスから買い候補を作成する。
5. 各買い候補について、6通りのデッドクロスによる売却候補を作成する。
6. 6通りの売却戦略を独立してシミュレーションする。
7. 全取引明細を作成する。
8. 全期間、前半70%、後半30%を集計する。
9. 入力と結果をJSONファイルへ保存する。

## フォルダとファイル

実行ごとに次の形式のフォルダを使用する。

```text
data/タスク/2_Gold売買検証/1_Goldの売買タイミング/YYYYMMDDHHmm/
```

入力データの準備フォルダは次のとおり。

```text
data/タスク/2_Gold売買検証/1_Goldの売買タイミング/202608260202/
```

今回の実行フォルダは次のとおり。

```text
data/タスク/2_Gold売買検証/1_Goldの売買タイミング/202608261429/
```

バックテストを実行したときに保存されるファイルは次の4つ。

| ファイル                | 内容                                         |
| ----------------------- | -------------------------------------------- |
| `market_history.json`   | MCPから取得したM5、M15、M30の入力データ      |
| `ma_crosses.json`       | 各時間足で検出したクロスの一覧               |
| `backtest_trades.json`  | 6戦略の全取引明細                            |
| `backtest_summary.json` | 検証設定、データ範囲、警告、期間別集計       |

戦略IDは次の形式とする。

```text
デッドクロスだけ: death_<時間足>_5_<比較対象期間>
```

例は次のとおり。

```text
death_M5_5_20
death_M15_5_60
```

取引明細の`exit_reason`は次のいずれかとなる。

| 値            | 内容                                 |
| ------------- | ------------------------------------ |
| `death_cross` | デッドクロス確定後の次バー始値で売却 |
| `force_close` | 共通検証期間の末尾で強制決済         |

実行フォルダは`--run-directory`で指定できる。

バックテスト結果のファイル名は上表の固定名とする。

既存ファイルがある場合は上書きせず、明示的に`--overwrite`を指定した場合だけ置き換える。

JSONは一時ファイルへ完全に書き出してから出力先へ置き換える。

入力JSONを正規化して計算したSHA-256を、クロス、取引明細、集計結果へ記録する。

## 検証手順

### 1. MT5 MCPの接続確認

最初に`get_workspace_info`を実行する。

失敗した場合はMetaTrader 5を起動する。

```bash
open -a "MetaTrader 5"
```

Docker Composeの状態を確認し、必要に応じて起動または復旧する。

```bash
docker compose ps
docker compose up -d
```

接続できない状態ではデータを推測せず、検証を開始しない。

### 2. データ取得

MT5 MCPからGOLDのM5、M15、M30を取得する。

取得処理ではMT5への注文、ポジション変更、決済を行わない。

取得結果を次の形式で1つのJSONへまとめる。

```json
{
  "datasets": [
    {
      "symbol": "GOLD",
      "period": "M5",
      "data_available_from": "<MCPが返した日時>",
      "history": []
    },
    {
      "symbol": "GOLD",
      "period": "M15",
      "data_available_from": "<MCPが返した日時>",
      "history": []
    },
    {
      "symbol": "GOLD",
      "period": "M30",
      "data_available_from": "<MCPが返した日時>",
      "history": []
    }
  ]
}
```

### 3. バックテスト実行

リポジトリのルートで次を実行する。

```bash
docker compose exec -T app /project/.venv/bin/python scripts/find_ma_crosses.py \
  --input /data/タスク/2_Gold売買検証/1_Goldの売買タイミング/202608260202/market_history.json \
  --run-directory /data/タスク/2_Gold売買検証/1_Goldの売買タイミング/202608261429 \
  --ma-periods 5,20,60 \
  --ma-method SMA \
  --applied-price CLOSE \
  --end-bar-shift 1 \
  --scan-from "2024.08.26 00:00:00" \
  --scan-to "2026.08.26 00:00:00" \
  --backtest \
  --moving-average-exits-only \
  --point-size 0.01 \
  --digits 2 \
  --cost-mode none \
  --split-ratio 0.7 \
  --expected-symbol GOLD
```

### 4. 出力確認

次を確認する。

- 4つのJSONファイルが存在する。
- 3つの結果ファイルの`input_sha256`が一致する。
- `strategy_count`が6である。
- 各取引で買い時刻が売り時刻より前である。
- 買いシグナル確定時刻が買い時刻より後になっていない。
- 売りシグナル確定時刻が売り時刻より後になっていない。
- `warnings`に記録された期間短縮や入力上の注意を確認する。

# 備考

- この資料は検証条件、再現手順、検証結果を記録する。
- 売却条件の順位と最良条件の判断基準は、本資料では定義しない。
- M5が指定した2年間を満たしていないため、検証実行後も「完全な過去2年間の検証」とは扱わない。
- データ取得範囲、コスト前提、売買ルールを変更した場合は別の実行フォルダを作成し、既存結果と混在させない。
- 本検証にはスプレッド、手数料、スリッページ、スワップ、実際の約定拒否、流動性の影響を含めない。
- 過去データ上で成績が高い条件が将来も同じ成績になるとは限らない。
