# 起動・接続確認

新しい実行セッションでは、必ず次の順番で実行する。

1. 最初のMT5 MCP操作として`get_workspace_info`を実行する。

2. `get_workspace_info`が成功した場合は、データ取得へ進む。

3. `get_workspace_info`が失敗した場合は、処理を終了せず、次を実行する。

```bash
docker compose ps
```

4. Docker Composeのサービスが起動していない、停止している、異常終了している、または状態を確認できない場合は、次を実行する。

```bash
docker compose up -d
```

5. Docker Composeのサービスが起動済みに見える場合でも、MT5 MCPへ接続できない場合は復旧処理として次を実行する。

```bash
docker compose up -d
```

6. `docker compose up -d`実行後、数秒待ってから次を確認する。

```bash
docker compose ps
```

7. その後、`get_workspace_info`を再実行する。

8. 再実行に失敗した場合は、短い待機を挟み、最大3回まで`get_workspace_info`を再試行する。

9. 最大3回再試行しても`get_workspace_info`が成功しない場合だけ、次のように扱う。

* データ取得エラーとして記録する。
* 買い候補にしない。
* 売り候補にしない。
* Slackへ通知しない。
* LINEへ通知しない。
* 接続失敗だけを理由に相場状況を推測しない。
* Dockerの確認結果、起動コマンドの結果、再試行回数、最後のエラーを最終報告へ記載する。

10. `get_workspace_info`に失敗したまま、チャート分析へ進まない。

11. DockerまたはMT5 MCPの起動・復旧操作は行うが、MT5への注文、ポジション変更、決済は絶対に行わない。

# M5の扱い

M5は最終方向を単独で決定する時間足ではなく、直近タイミングの補助確認として使用する。

買い方向では次を補強材料とする。

* 上位時間足が買い方向で、M5でも安値を切り上げている。
* M5で価格がSMA20付近から反発している。
* M5でSMA5が下向きから上向きへ戻っている。
* M5で陽線の実体がSMA5を下から上へ抜いている。
* M5で直近高値を突破している。
* M5で短期SMAが密集後に上方向へ広がっている。

売り方向では次を補強材料とする。

* 上位時間足が売り方向で、M5でも高値を切り下げている。
* M5で価格がSMA20付近から反落している。
* M5でSMA5が上向きから下向きへ戻っている。
* M5で陰線の実体がSMA5を上から下へ抜いている。
* M5で直近安値を割っている。
* M5で短期SMAが密集後に下方向へ広がっている。

M5について次の場合は通知を急がない。

* M15以上の方向と明確に逆方向へ動いている。
* 短期SMAが密集している。
* SMA5、SMA20、SMA60がもつれている。
* 直近高値・安値を更新していない。
* 反発・反落の途中で方向が確定していない。
* 8～10本程度一方向へ動いた後である。

M5単独のクロス、RSI、ローソク足1本だけでは通知しない。

* SMA20、SMA60が上向き。

* SMA5が下向きから上向きへ戻る。

* 価格が前の高値を突破する。
* SMA5が前の高値を突破する。
* SMA10が前の高値を突破する。
* 短期SMAが密集後に上方向へ広がる。
* SMA20がSMA60を上抜く。
* 下降後、前の安値を割れずに反発する。
* 下降後、高値と安値が切り上がり始める。

* SMA5が前の安値を割る。

* 短期SMAが密集後に下方向へ広がる。
* SMA20がSMA60を下抜く。
* 上昇後、前の高値を越えられず反落する。

# 押し目買い

上昇トレンド中の一時的な下落は、すぐ売り転換と判断しない。

次を確認する。

* SMA20、SMA60が上向き。
* 価格がSMA20またはSMA60付近まで下落。
* SMA20またはSMA60を大きく割らない。
* 前の安値を割らない。
* SMA5が再び上向く。
* 陽線でSMA5を上抜く。
* その後、高値更新を狙う動きになる。

複数確認できれば買い方向を強く評価する。

M5では、上位時間足の押し目候補に対して反発開始のタイミング確認として使用する。

* 価格がSMA20またはSMA60付近まで上昇。
* SMA20またはSMA60を大きく越えられない。
* 前の高値を越えられない。
* SMA5が再び下向く。

* 前の高値を突破する。

売り方向では、次の順番を強く評価する。

* 前の高値を越えられない。
* 高値を切り下げる。
* 前の安値を割る。

# SMA20とSMA60

SMA20とSMA60の関係は中期方向の確認材料として使用する。

* SMA20＞SMA60かつ両方上向き

  * 上昇方向を補強。

* SMA60＞SMA20かつ両方下向き

  * 下降方向を補強。

* SMA20がSMA60を下から上へ抜く

  * 上昇転換の補強。

* SMA20がSMA60を上から下へ抜く

  * 下降転換の補強。

クロスだけでは通知しない。

# トレンドの継続本数

特定の名称は使わず、単純に直近の継続本数として確認する。

* 同方向の値動きが何本継続しているか数える。
* 4～7本程度続いた場合は勢いの変化に注意する。
* 8～10本程度続いた場合は、追いかけて新規エントリーするリスクが高いと判断する。

特に次の場合はトレンド失速として扱う。

* SMA5が横ばいになる。
* 高値を更新できなくなる。
* 安値を更新できなくなる。
* 反対方向の強いローソク足が出る。

継続本数だけを理由に逆方向へ判断しない。

M5についても同様に確認するが、M5の継続本数だけを理由に上位時間足の方向を否定しない。

# 買い候補条件

以下をすべて満たす場合だけ買い候補とする。

* 買い方向の具体的なシグナルが1件以上ある。
* 買い根拠を3点以上説明できる。
* 3点が単一指標だけではない。
* M15、M30、H1、H4のうち2時間足以上が上昇方向。
* H1またはH4の少なくとも一方が明確な上昇方向。
* D1が強い下降方向ではない。
* H1、H4、D1に強い下降方向の矛盾がない。
* 明確な売り条件がない。
* 8～10本程度上昇した後の追いかけ買いではない。
* M5を確認し、直近の明確な売り方向への反転が発生していない。
* M5が買い方向ならタイミング補強材料とする。
* M5が横ばいまたは判定不可の場合、M5だけを理由に買い候補にはしない。
* M5が明確な下降方向で、上位時間足との整合性について判断に迷う場合は通知しない。
* データがすべて揃っている。
* technical_chart.pyがすべて成功している。

買い根拠の例:

* H4でSMA5＞SMA20＞SMA60かつ3本とも上向き。
* H1でSMA20付近から反発。
* M30で陽線がSMA5を上抜いた。
* M30で前の高値を突破。
* M15で短期SMAが上方向へ広がった。
* M5で安値切り上げ後に直近高値を突破した。
* M5で短期SMAが密集後に上方向へ広がり始めた。

ただし、M5だけを買い方向の具体的シグナルとして買い候補にしない。

* D1が強い上昇方向ではない。
* H1、H4、D1に強い上昇方向の矛盾がない。
* 明確な買い条件がない。
* 8～10本程度下降した後の追いかけ売りではない。
* M5を確認し、直近の明確な買い方向への反転が発生していない。
* M5が売り方向ならタイミング補強材料とする。
* M5が横ばいまたは判定不可の場合、M5だけを理由に売り候補にはしない。
* M5が明確な上昇方向で、上位時間足との整合性について判断に迷う場合は通知しない。
* データがすべて揃っている。
* technical_chart.pyがすべて成功している。

売り根拠の例:

* H4でSMA60＞SMA20＞SMA5かつ3本とも下向き。
* H1でSMA20付近まで戻した後に反落。
* M30で陰線がSMA5を下抜いた。
* M30で前の安値を割った。
* M15で短期SMAが下方向へ広がった。
* M5で高値切り下げ後に直近安値を割った。
* M5で短期SMAが密集後に下方向へ広がり始めた。

ただし、M5だけを売り方向の具体的シグナルとして売り候補にしない。

# 見送り条件

次の場合は通知しない。

* 判断に迷う。
* 必要項目が判定不可。
* データ不足。
* `get_workspace_info`が復旧処理後も失敗している。
* `get_chart_history`が失敗している。
* technical_chart.pyが失敗している。
* D1、H4、H1の方向が大きく食い違う。
* 買い条件と売り条件が同時に成立。
* 単一時間足しか根拠がない。
* 単一指標しか根拠がない。
* SMAクロスしか根拠がない。ただし、後述のM30・H1クロス通知は売買候補通知とは独立して実行する。
* RSIしか根拠がない。
* 1本のローソク足しか根拠がない。
* M5だけしか根拠がない。
* M15だけしか根拠がない。
* M30だけしか根拠がない。
* SMA5、SMA20、SMA60が横ばいでもつれている。
* 短期SMAが密集しているだけで方向が出ていない。
* すでに一方向へ8～10本程度大きく動いた後の追いかけになる。
* 上位時間足が候補条件を満たしていても、M5で強い反対方向への動きが発生し、押し・戻りなのか転換なのか判断できない。

# 最終方向

  * 買い候補

* 売り条件だけ成立

  * 売り候補

* 両方成立

  * 見送り

* どちらも成立しない

  * 見送り

# ゴールデンクロス・デッドクロス判定と通知

この通知は買い候補・売り候補の判定とは独立して実行する。
クロスだけを理由に買い候補・売り候補とは判断しない。
注文、ポジション変更、決済は行わない。

## 判定対象

独立したクロス判定の対象時間足はM30とH1の2種類だけとする。
M5、M15、H4、D1では独立したクロス判定およびクロス通知を行わない。

`technical_chart.py`の確定バー（`bar-shift: 1`）の結果を使用する。

* M30:
  * SMA5とSMA20のゴールデンクロス / デッドクロス
  * SMA5とSMA60のゴールデンクロス / デッドクロス
* H1:
  * SMA5とSMA20のゴールデンクロス / デッドクロス
  * SMA5とSMA60のゴールデンクロス / デッドクロス

`クロスなし`、`判定不可（データ不足）`の場合はクロス通知しない。
該当時間足のデータ取得または`technical_chart.py`が失敗した場合は、結果を推測せずクロス通知しない。

## 通知先

* M30で1件以上のクロスを検出した場合:
  * slackへ1回通知する。
  * lineへは通知しない。
* H1で1件以上のクロスを検出した場合:
  * slackへ1回通知する。
  * lineへ1回通知する。

同じ時間足・同じ分析対象バーで複数の移動平均ペアが同じクロス種別に該当した場合は、同じ通知文言を1回だけ送信する。
同じ時間足・同じ分析対象バーでゴールデンクロスとデッドクロスの両方に該当した場合は、該当する2つの通知文言をそれぞれ送信する。
M30とH1が同じ実行でクロスした場合は、時間足ごとに該当する通知文言を送信する。

## クロス通知コマンド

```bash
docker compose exec -T app pipenv run python scripts/send_message.py \
  <slack または line> \
  --message '<クロス通知メッセージ>'
```

## クロス通知文言

通知本文は該当する次の文言だけとし、説明、数値、記号、接頭辞、接尾辞を追加しない。

* M30でゴールデンクロスに該当: `30分足でゴールデンクロス`
* M30でデッドクロスに該当: `30分足でデッドクロス`
* H1でゴールデンクロスに該当: `1時間足でゴールデンクロス`
* H1でデッドクロスに該当: `1時間足でデッドクロス`

複数の文言に該当した場合は、該当する文言をそれぞれ送信する。

## クロス通知の重複防止

次がすべて同じクロス通知をすでに送信済みの場合は再通知しない。

* 銘柄
* 時間足
* 分析対象の確定バー時刻
* クロス種別

対象SMAペアが異なっても、時間足、分析対象の確定バー時刻、クロス種別が同じ場合は、同じ通知文言を再送しない。
H1の同じ確定バーを毎時30分の実行で再判定しても再通知しない。
同じ分析対象バーでゴールデンクロスとデッドクロスの両方に該当した場合は、各通知文言を1回ずつ送信する。

# 最重要

次だけで売買候補と判断しない。

* 1本のローソク足
* ゴールデンクロス
* デッドクロス
* RSI
* SMA5だけ
* M5だけ
* M15だけ
* M30だけ

必ず次を組み合わせて判断する。

* SMAの並び
* SMAの傾き
* 大きな相場方向
* 高値と安値
* 押し・戻り
* 短期SMAの密集と拡散
* SMA20とSMA60
* 直近の値動き
* 複数時間足

M5は必ず取得・分析するが、M5単独で方向を決めない。

M5は主に次の確認に使用する。

* 上位時間足の方向に対する直近タイミング
* 押し目からの反発開始
* 戻りからの反落開始
* 高値・安値の更新
* 短期SMAの密集から拡散への変化
* 上位時間足とは逆方向の短期的な動き
* エントリーを追いかける状態になっていないか

強い上昇トレンド中のM5の一時的な下落は、すぐ売り転換と判断せず、押し目の可能性を考える。

強い下降トレンド中のM5の一時的な上昇は、すぐ買い転換と判断せず、戻りの可能性を考える。

強い上昇トレンド中の一時的な下落は、押し目の可能性を考える。

強い下降トレンド中の一時的な上昇は、戻りの可能性を考える。

明確な転換を確認するまでは、大きなトレンドと逆方向の候補を出さない。

`get_workspace_info`の失敗だけで処理を終了しない。

`get_workspace_info`に失敗した場合は、DockerとMT5 MCPが起動しているかを確認し、必要な起動・復旧処理を自分で行ってから再試行する。

Dockerが停止している可能性を確認せずに「接続できなかった」で終了しない。

取得していないニュース、経済指標、ファンダメンタルズ、保有ポジションは判断材料に使用しない。

MT5への注文、ポジション変更、決済は絶対に実行しない。
