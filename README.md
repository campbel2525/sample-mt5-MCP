# 概要

MT5にMCPの機能が追加されてAIから簡単に利用できるようになりました

MCPを使うと

- MT5からチャートの情報を取得できる
- 売買をMT5から取得できる
- チャートの情報を取得できるのでAIに分析してもらえる

と言いたメリットがあります。

今回は以下の流れを想定しています。

1. MCP経由でMT5からチャートの情報を取得
2. こちらで用意したPythonを利用してテクニカルチャートの計算を行う
3. AIで操作を行う

- 売買を行う
- Slack, Lineにメッセージを送信する

実行環境は以下の通り

- MT5をMAC上で実行し適切にMT5のMCPの設定を行う
- Docker上でcodexを実行
- codexは定期的に実行しチャートの分析を行い売買を行う

# 詳細

## 1. MCP経由でMT5からチャートの情報を取得

MCPから取得されるデータ情報

```
{
  "symbol": "BTCUSD",
  "period": "H1",
  "data_available_from": "2013.01.01 00:00:00",
  "history": [
    {
      "time": "2026.08.15 19:00:00",
      "open": 63075.25,
      "high": 63101.75,
      "low": 63040.25,
      "close": 63072.45,
      "tick_volume": 193,
      "spread": 4000
    }
  ]
}
```

## 2. こちらで用意したPythonを利用してテクニカルチャートの計算を行う

`scripts/technical_chart.py`は、MCPから取得したJSONを読み込み、次の結果を箇条書きで出力します。

- 短期移動平均線と長期移動平均線のクロス判定
- 短期移動平均線と中期移動平均線のクロス判定
- RSIの値

MCPから取得したJSON文字列を`--market-json`に指定して実行します。JSON文字列はシェルに展開されないようにシングルクォートで囲みます。

```bash
docker compose exec app python scripts/technical_chart.py \
  --ma-periods 5,20,60 \
  --ma-method SMA \
  --applied-price CLOSE \
  --rsi-period 14 \
  --bar-shift 1 \
  --market-json \
  '{"symbol":"BTCUSD","period":"H1","data_available_from":"2013.01.01 00:00:00","history":[{"time":"2026.08.15 19:00:00","open":63075.25,"high":63101.75,"low":63040.25,"close":63072.45,"tick_volume":193,"spread":4000}]}'
```

引数は次のとおりです。

- `--ma-periods`: 短期、中期、長期の移動平均期間。既定値は`5,20,60`
- `--ma-method`: 移動平均方式。`SMA`、`EMA`、`SMMA`、`LWMA`から指定。既定値は`SMA`
- `--applied-price`: MAとRSIの適用価格。`CLOSE`、`OPEN`、`HIGH`、`LOW`、`MEDIAN`、`TYPICAL`、`WEIGHTED`から指定。既定値は`CLOSE`
- `--rsi-period`: RSIの期間。既定値は`14`
- `--bar-shift`: 判定対象を最新バーから何本戻すか。`0`は最新バー、`1`は1本前。既定値は`1`
- `--market-json`: MCPから取得したJSON文字列

出力例

```text
- 短期移動平均線と長期移動平均線: ゴールデンクロス
- 短期移動平均線と中期移動平均線: クロスなし
- RSI: 63.42
```

指定した移動平均期間とRSI期間に対して履歴が不足している場合は、`判定不可（データ不足）`または`算出不可（データ不足）`を出力します。

# 実行プロンプト

```
MT5のチャートを監視し、テクニカル分析結果に応じて買い候補を通知してください。

このタスクは分析と通知のみを行います。
MT5への注文、ポジション変更、決済は行わないでください。

ゴールデンクロスまたはデッドクロスが検出されても、それだけを理由に通知しないでください。
クロス情報は、買い候補を判断するための分析材料としてのみ使用してください。

## 設定

- 対象銘柄: <MT5の正確なシンボル名>
- 通知先: <slack または line>
- 対象時間足:
  - M15（15分足）
  - M30（30分足）
  - H1（1時間足）
  - H4（4時間足）
  - D1（日足）
- 使用するローソク足: 各時間足の最新65本
- 移動平均期間: 5,20,60
- 移動平均方式: SMA
- 適用価格: CLOSE
- RSI期間: 14
- bar-shift: 1

## 実行手順

1. 新しい実行セッションでは、最初にMT5 MCPのget_workspace_infoを呼び出してください。

2. MT5 MCPのget_chart_historyを使用し、対象銘柄についてM15、M30、H1、H4、D1のチャートを取得してくださ
い。

3. get_chart_historyには、実行時点をdatetime_toとして指定してください。

4. 各時間足について65本以上取得できるようにdatetime_fromを指定してください。

5. 取得結果をtimeの昇順に並べ、末尾の最新65本だけを使用してください。

6. 65本未満しか取得できなかった時間足は分析対象外にしてください。不足データから結果を推測しないでくださ
い。

7. 各時間足について、次の形式のJSONを作成してください。

{
  "symbol": "<対象銘柄>",
  "period": "<時間足>",
  "data_available_from": "<MCPの取得結果>",
  "history": [最新65本のローソク足]
}

8. 各JSONを1つずつ、次のコマンドの--market-jsonへ安全に渡して実行してください。

docker compose exec -T app python scripts/technical_chart.py \
  --ma-periods 5,20,60 \
  --ma-method SMA \
  --applied-price CLOSE \
  --rsi-period 14 \
  --bar-shift 1 \
  --market-json '<JSON文字列>'

9. コマンドが失敗した時間足については、結果を推測せずエラーとして記録してください。

10. 各時間足について、次の結果を整理してください。

- 短期移動平均線と長期移動平均線のクロス状況
- 短期移動平均線と中期移動平均線のクロス状況
- RSI
- 分析対象となったバーの時刻
- 直近の値動き

## クロス情報の扱い

ゴールデンクロスおよびデッドクロスは、買い候補を判断するための分析材料としてのみ使用してください。

次の場合でも、クロス単独の通知は送信しないでください。

- H1でゴールデンクロスが検出された
- H4でゴールデンクロスが検出された
- D1でゴールデンクロスが検出された
- H1でデッドクロスが検出された
- H4でデッドクロスが検出された
- D1でデッドクロスが検出された
- 複数の時間足でクロスが検出された

デッドクロスが検出された場合は、買い候補を見送るべきリスクとして評価してください。

## 買い候補の判断

M15、M30、H1、H4、D1の取得データと分析結果を総合的に確認してください。

買い候補通知は、次の条件をすべて満たす場合だけ送信してください。

- 複数の時間足が上昇方向を示している
- H1、H4、D1に明確な下落方向の矛盾がない
- ゴールデンクロス、RSI、直近の値動きなど、確認済みデータから具体的な根拠を3点以上説明できる
- 単一時間足の結果だけに依存していない
- データ不足がない
- 時間足間に強い矛盾がない

単一時間足のゴールデンクロスまたはRSIだけを根拠に、買い候補と判断しないでください。

取得していないニュース、出来事、指標、保有ポジションなどを根拠にしないでください。

判断に迷う場合、根拠が弱い場合、または時間足間で結果が矛盾する場合は、買い候補通知を送信しないでくださ
い。

## 買い候補通知

買い候補と判断した場合だけ、project/scripts/send_message.pyを利用して通知してください。

通知には次の内容を含めてください。

- 「買い候補」であり、注文を指示するものではないこと
- 対象銘柄
- 判断根拠
- 各時間足のクロス状況
- 各時間足のRSI
- 直近の値動き
- 判断を見送るべきリスク
- 分析対象となったバーの時刻
- 実行日時
- lineとslackの両方

通知コマンド:

docker compose exec -T app python scripts/send_message.py \
  <slack または line> \
  --message '<買い候補メッセージ>'

条件を満たさない場合は、通知を送信しないでください。

同じ分析対象バーと同じ判断根拠による買い候補を、すでにこのチャットで通知している場合は再通知しないでくだ
さい。

## 最終報告

実行後、次の内容を簡潔に報告してください。

- 各時間足の分析結果
- 買い候補と判断したか
- 通知を送信したか
- 通知しなかった場合はその理由
- データ取得またはコマンド実行のエラー

ゴールデンクロスまたはデッドクロスだけを通知したと報告しないでください。

確認できなかった内容を推測で補完しないでください。
```
